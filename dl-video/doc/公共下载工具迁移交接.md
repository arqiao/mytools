## 2. 解析、认证与限制

配置来自显式参数，没有隐式业务配置文件。公共默认 profile 是 `~/.local/state/arqiao-tools/media-download/browser`；本机现有账号仍通过参数引用 dl-video 的 `.browser_data_wxchannels`。没有复制浏览器目录、导出 Cookie/storage_state 文件、迁移凭据或新增账号。

Playwright 仅为内存读取既有 profile Cookie 启动 Chromium；正常解析优先 requests HTTP，无需加载元宝页面。HTTP getuserinfo 必须确认真实用户标识且非 anonUser；匿名 200 不是有效登录。需要回退时复用同一个 browser context，最多一次，不反复开登录窗口。

| 场景 | 实际行为 |
|---|---|
| HTTP 正常 | getuserinfo → get_parse_result；只产生一份解析结果 |
| 原接口 | wx_export_id → findergetobjecturl → videoUrl |
| 备用接口 | playable_url 的 token + eid（缺 eid 可取 wx_export_id）→ get_feed_info；使用独立无元宝 Cookie 的 HTTP Session |
| auto 取流 | 有 export_id 默认先原接口；无 export_id 但有 token/eid 直接备用 |
| 显式编码 | 有 token/eid 时直接选择备用接口对应 h264VideoInfo/h265VideoInfo，再以 ffprobe 核实；缺所需流就失败 |
| 原接口缺字段/网络/5xx | 已有 token/eid 时允许转备用一次，不重新解析分享链接 |
| 解析阶段网络/5xx/字段变化 | 有限 HTTP 重试后，允许一次浏览器页面解析回退 |
| 未登录/认证过期/403 | 返回 auth_missing/auth_expired/permission_denied；headless 下停止，不绕过认证或反复切接口 |
| 空解析/限流/未知业务错误 | 分别 parse_empty/rate_limited/business_error，停止 |
| 可见登录 | 只有显式 no-headless 才允许同一会话等待用户登录；本轮未使用 |

实测发现备用 get_feed_info 返回 HTTP 201，已兼容 200/201，并继续检查业务码和 feedInfo；不能仅靠状态码认定解析成功。已补 201 回归。两条真实接口的签名 URL 不同，但完整下载后的 SHA-256 相同。

仅允许规范 sph 来源、固定元宝/微信接口和 HTTPS finder.video.qq.com 媒体；API HTTP 与媒体不跟随重定向，浏览器 API fetch 使用 redirect:error。签名 URL、token、wx_export_id、Cookie 和原始异常只在必要进程内使用，不进入 JSON/日志/成功清单。第三方协议参考及 MIT 署名见公共工具 `THIRD_PARTY_NOTICES.md` 与 `licenses/video-transcript-MIT.txt`，未打包整个第三方仓库。

限额语义：

- 单次 `download` 只处理一个链接、最多一个媒体 GET。API 网络/5xx 默认重试一次，可设 0–2；媒体无自动重试，调用方不能无限重试失败回执。
- 公共默认 64 MiB。有 Content-Length 先准入、后核对；无长度按剩余额度读取，达到上限但无法确认 EOF 时保守失败。received_bytes/written_bytes 是应用媒体正文计数，不是含 TLS/TCP 或系统 socket 缓冲的总流量。
- request-timeout 默认 30 秒，是连接/空闲读取超时，非总任务期限。锁等待 30 秒；可见登录等待默认 300 秒；ffprobe 60 秒，单次解码/提取 max(300 秒, 时长×2)。
- 默认 MP4 头/box 边界、流/时长、完整严格解码全部通过后才无覆盖发布。兼容旧 verify_decode=false 时回执明确标记弱化校验。
- 唯一临时文件 + 同资产 flock + 无覆盖 hard-link 发布。失败分片不会冒充完成；没有实现 Range 断点续传。
